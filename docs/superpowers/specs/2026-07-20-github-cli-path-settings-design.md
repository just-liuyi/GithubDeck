# GitHub CLI 可执行文件设置设计

## 目标

删除应用中的浏览器扫描、浏览器偏好和浏览器设置操作，将齿轮设置改为 GitHub CLI 可执行文件设置。应用默认使用：

`C:\Program Files\GitHub CLI\gh.exe`

用户可以通过 Windows 文件选择器指定其他 `gh.exe`，设置会跨应用重启持久保存，并用于刷新账号、切换账号和登录新账号的全部 GitHub CLI 操作。

## 设置界面

齿轮按钮的工具提示和辅助名称改为“GitHub CLI 设置”。对话框包含：

- 只读的当前 `gh.exe` 绝对路径。
- “选择 gh.exe”按钮，打开仅选择可执行文件的文件选择器。
- “恢复默认”按钮，将候选路径恢复为默认安装路径。
- 校验结果区域。
- 保存和取消按钮。
- 来源说明：GitHub CLI 来自 `https://github.com/cli/cli/releases/`，需要下载并安装对应的 Windows MSI。
- 已测试版本说明：`gh_2.96.0_windows_amd64.msi`。

官方来源地址以可点击链接显示，并允许 Qt 使用系统默认浏览器打开。文件选择器默认定位到当前路径所在目录；取消文件选择时不改变候选路径。

## 路径与持久化

新增单一职责的 GitHub CLI 路径配置对象，封装 `QSettings`：

- 设置键不存在时返回默认路径。
- 保存时存储规范化后的绝对路径。
- 恢复默认时删除设置键，而不是重复保存默认值。
- 已保存文件后来失效时仍保留该路径供用户修正，不静默切回默认路径。

进程层不再引用固定全局常量，而是在每次操作启动时读取配置对象当前路径。这样设置保存后立即作用于后续操作，无需重启应用。

## 校验规则

保存设置前必须同时满足：

1. 路径指向真实存在的普通文件。
2. 文件名不区分大小写等于 `gh.exe`。
3. 以参数数组方式执行 `<候选路径> --version`，在有限超时内成功退出。
4. 输出能够识别为 GitHub CLI 版本信息。

不强制版本必须等于 2.96.0；界面只将 `gh_2.96.0_windows_amd64.msi` 声明为已测试版本。校验失败时不保存、不关闭对话框，并显示安全的中文错误，不回显任意原始进程输出。

版本校验不得使用 shell 字符串拼接。校验期间界面禁用保存和选择操作，避免重复启动。校验完成后恢复交互。

## 运行行为

刷新、切换和登录启动前继续检查当前配置路径是否存在。无效时不启动进程，主窗口显示：

`未找到 GitHub CLI，请在设置中指定有效的 gh.exe`

所有操作继续使用 `QProcess` 和参数数组。Token 环境变量隔离、设备码解析、授权网址显示、复制重试、取消和超时逻辑保持不变。

浏览器相关行为全部删除：

- 不扫描 Edge、Chrome 或 Firefox。
- 不保存浏览器路径。
- 不设置 `GH_BROWSER`。
- 登录由 GitHub CLI 使用系统默认浏览器打开设备授权页。

## 代码边界

- 删除浏览器模型、注册表扫描和浏览器偏好实现。
- 将浏览器设置对话框替换为 GitHub CLI 设置对话框。
- 主窗口只依赖 GitHub CLI 路径设置，不再依赖浏览器扫描器。
- 进程对象接收同一个路径设置对象，并在每次操作开始时解析路径。
- 应用默认构造链确保主窗口、控制器和进程共享一致的路径设置。

## 测试标准

自动化测试覆盖：

- 无设置时返回默认路径。
- 保存自定义绝对路径并跨配置对象读取。
- 恢复默认删除设置键。
- 文件选择取消和成功选择。
- 非 `gh.exe`、不存在文件、超时、非 GitHub CLI 输出和非零退出均拒绝保存。
- 合法 `gh.exe --version` 允许保存，且 2.96.0 之外的有效版本也允许。
- 刷新、切换和登录全部使用当前配置路径。
- 设置保存后无需重启即可用于下一次操作。
- 登录环境不再设置或继承 `GH_BROWSER`。
- 原有账号解析、异步状态、授权码、复制、取消和超时测试继续通过。

验证不得执行真实 GitHub 登录或账号切换。完整 pytest、uv 锁文件检查和 Python 编译检查必须通过。
