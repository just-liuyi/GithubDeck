# GitHub CLI 多账号管理器视觉设计

## 目标

在不改变现有账号管理、设备授权和 GitHub CLI 路径设置行为的前提下，将 PySide6 界面重写为“GitHub 专业控制台”风格。界面应保持 Windows 桌面工具的紧凑性，并使用接近 GitHub 产品的中性灰层级、绿色主操作色和蓝色选择态。

## 视觉系统

- 应用背景使用 GitHub 风格的浅灰 `#f6f8fa`，内容表面使用白色。
- 标题栏使用深灰 `#24292f`，文字使用接近白色的 `#f0f6fc`。
- 边框使用 `#d0d7de`，强调边框使用 `#afb8c1`。
- 正文使用 `#1f2328`，次要文字使用 `#656d76`。
- 登录等主操作使用绿色 `#1f883d`；账号选中态使用蓝色 `#0969da`；错误使用红色 `#cf222e`。
- 控件使用 6px 左右的小圆角和轻微阴影，避免网页式大圆角和装饰性渐变。
- 字体使用 Windows 和中文系统字体栈，整体保持桌面工具的紧凑密度。

## 主窗口结构

主窗口默认尺寸约为 820×620，最小尺寸应保证按钮、账号信息和授权区域不重叠。内容由上至下分为四层：

1. 深色应用标题栏，显示应用名称。
2. 页面标题区，左侧显示“GitHub 账号”和简短说明，右侧放置“刷新”和“GitHub CLI 设置”。
3. 账号内容区，显示账号计数和账号卡片列表。
4. 底部操作区及状态栏。

账号卡片显示头像缩写、登录名、主机、认证状态和当前账号标识。当前账号使用绿色左侧强调线和“当前账号”徽标；用户选中的账号使用蓝色边框。只有选中非当前账号时，“切换到所选账号”按钮才可用。

## 设备授权状态

点击“登录新账号”后，在账号列表下方展开蓝色浅底授权面板，不打开独立向导。面板显示：

- “在浏览器中完成 GitHub 授权”标题。
- 应用不会读取或保存 Token 的说明。
- 只读官方设备授权网址及“复制网址”按钮。
- 只读一次性授权码及“复制授权码”按钮。
- “取消登录”操作。

授权流程结束或取消后收起该面板并清空授权码。现有剪贴板重试和旧登录会话隔离逻辑保持不变。

## GitHub CLI 设置

设置继续使用模态对话框，并与主窗口共享同一视觉系统。对话框包含：

- 只读 `gh.exe` 路径。
- “选择 gh.exe”和“恢复默认”操作。
- 校验状态反馈。
- GitHub CLI 官方发布页链接。
- Windows MSI 下载说明。
- 已测试安装包 `gh_2.96.0_windows_amd64.msi`。
- 保存和取消按钮。

保存期间继续允许取消；只有异步校验成功后才写入配置并关闭对话框。合法的其他 GitHub CLI 版本仍允许保存。

## 状态与错误反馈

主窗口底部状态栏显示连接状态、最近操作结果和 GitHub CLI 版本信息。普通状态使用中性色和绿色状态点；错误消息使用红色文字及错误状态点，但不显示 GitHub CLI 原始输出。

忙碌期间禁用账号列表、刷新、登录、设置和切换操作。设备登录活动期间显示取消操作。视觉禁用态必须与现有控制器状态保持同步，不增加新的业务状态。

## 组件边界

- `MainWindow` 负责主窗口布局、账号卡片渲染、授权面板和状态展示。
- 账号数据仍由现有 `Account` 模型和 `AuthController` 信号提供。
- `GhSettingsDialog` 负责路径选择、校验反馈和保存交互。
- 样式通过集中式 Qt Style Sheet 和少量控件属性表达，不复制控制器或进程逻辑。
- 如账号卡片需要自定义布局，应使用专用轻量 QWidget 项目组件；该组件只负责呈现账号和选中状态，不持有业务状态。

## 测试与验收

现有行为测试必须继续通过，并补充以下视觉结构测试：

- 主窗口关键控件保留现有 objectName，避免破坏行为测试和可访问性定位。
- 账号列表能呈现当前、已认证和需重新认证状态。
- 选择非当前账号时切换按钮启用，选择当前账号时禁用。
- 登录状态能展开和收起授权面板。
- 忙碌和错误状态能应用对应属性或样式。
- 设置对话框保存、取消、恢复默认和异步校验行为不变。

最终验收包括运行完整 pytest 测试套件，并在 Windows 上启动应用进行人工检查，确认窗口缩放、中文文本、按钮禁用态、列表滚动和设置弹窗均无裁切或重叠。
